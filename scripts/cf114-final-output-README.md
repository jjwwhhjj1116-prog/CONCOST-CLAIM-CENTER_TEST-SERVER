# CF114 actual final-output regression

This local-only fixture uses the production ReportBodyPages and downloadFinalDocument.
It creates a three-page synthetic report containing Korean paragraphs, nested ordered
lists, merged cells and a generated geometric image. It never calls live application APIs.

1. Start Vite in apps/web on 127.0.0.1:3020.
2. Start scripts/cf114-final-output-receiver.mjs with Node from the repository root.
3. Open http://127.0.0.1:3020/qa/cf114-output-export.html in the browser.
4. Click 실제 출력 3종 생성. The receiver saves only four allowlisted artifact names
   under artifacts/cf114. The receiver accepts only origin http://127.0.0.1:3020.
5. Run scripts/cf114-final-output-integrity.py with the bundled Python runtime
   (pypdf and Pillow required). It checks three page-image streams, page dimensions,
   DOCX drawing relationships and page breaks, HWPX archive integrity and image order.
6. Render artifacts/cf114/cf114-report.pdf using bundled pdftoppm and inspect every page.
7. Stop the receiver and Vite after QA.

PDF and DOCX are generated by the real downloadFinalDocument. The fixture intercepts
only the final blob-download click to save those bytes in the named local directory.
HWPX uses the production createHwpx with the same captured page images from DOCX;
it validates the HWP conversion intermediate, not the final binary HWP converter.
The separate 캡처 목록 검사 button measures raw html2canvas clone styles and is
diagnostic only; the production capture callback may explicitly preserve styles.

The generated PDF and DOCX contain raster pages by design. Searchable/editable text
parity is not claimed. Native Word/Hancom rendering must be verified separately
when those applications or a supported bundled renderer are available.
