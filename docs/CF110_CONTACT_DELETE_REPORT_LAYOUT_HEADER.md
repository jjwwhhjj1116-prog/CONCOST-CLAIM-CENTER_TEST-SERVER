# CF110 · 명함 삭제 / 초안 화면 간소화 / 보고서 머리글

## 변경 범위

- 인맥관리 일반 목록에 관리자용 삭제 버튼과 대상 이름을 확인하는 대화상자를 추가했다. 기존 ARCHIVE/RESTORE API와 관리자 권한·버전 검사를 유지한다. 목록에서 제거되지만 Drive 원본과 감사이력은 보존되며 명함 DB관리에서 복원한다.
- 요청 성공 후 목록을 즉시 갱신하므로 후속 조회 실패가 삭제된 카드를 그대로 남기지 않는다. 처리 중 중복 삭제를 막고 실패하면 재시도할 수 있다. 실제 업무 명함을 삭제하지 않았다.
- 보고서 STEP3의 산출서·내역자료 업로드와 CURRENT CHAPTER AGENT 표시 패널을 제거했다. 기존 Drive 자료·생성 근거·전역 문서 가져오기 메뉴는 유지한다.
- 초안 챕터 선택과 판례 근거를 같은 폭의 2열로 배치했다. 980px 이하에서는 1열이다. 긴 검색 결과는 접기/내부 스크롤로 확인하고, 선택 판례 상세는 기본 접힘이다.
- STEP3/4에서 머리글 사용 체크와 내용 편집을 제공한다. 표지·본문은 별개로 유지하며 첫 줄은 머리글 제목, 다음 줄은 보조정보로 표시한다. 기존 디자인과 컴포넌트를 재사용했다.

## 저장 및 출력

- 기존 versioned editor JSON의 `attrs.reportHeader`에 표시 여부·문구를 저장한다. 새 DB 컬럼이나 migration은 없다.
- `report-presentation.ts`의 split/join 경로를 사용한다. 본문 JSON과 표시 설정을 분리하므로 설정만 있는 JSON이 Markdown 본문을 빈 문서로 덮지 않는다.
- 로드·백업 복원 시 설정을 복구하고, 본문 편집·AI 작성·전체 문서 교체는 별도 머리글 상태를 유지한다. 저장 중 변경 감지도 머리글을 포함한다.
- 협업 APPLY는 새 본문과 함께 기존 머리글 설정을 draft/revision에 보존한다. 요청 중 머리글 수정은 잠가 응답 재로드로 입력이 유실되지 않게 한다.
- STEP3/4 미리보기와 최종 PDF·DOCX·HWP의 원본 DOM은 같은 `ReportFinalDocumentPreview`를 사용한다. 머리글을 끄면 본문 header 요소 자체가 제거된다.
- 기존 Node 서버에는 이 preview-mode 명함/보고서 draft API가 없다. 이번 변경이 새 Node API를 제공한다고 주장하지 않으며, 기존 Cloudflare 개발 서버 경로만 반영한다.

## 검증

- TypeScript 및 프로덕션 빌드 성공, 기존 번들 크기 경고만 유지.
- 관련 node:test 43/43 통과. 신규 helper·UI 계약 5개와 API의 머리글 저장/백업/협업/revision 보존, 권한·충돌·명함 복원/Drive 원본 불변 검증 포함.
- CF71 추가 검사 통과. 삭제된 업로드 패널 계약과 현재 백업 문구를 반영했으며, 공용 Excel 발췌 파서 검증은 유지했다.
- 독립 메모리 DB/API 검사에서도 삭제·복원 시 Drive 호출 0회, 원본 식별자·해시·크기 및 감사이력 보존을 확인했다.
- 레이아웃 검사 0건, `git diff --check` 통과.
- 브라우저 검수는 외부 쓰기가 차단된 로컬 합성 화면 `qa/cf108-outline.html?cf110=1`을 사용한다. 실제 업무 데이터를 변경하지 않는다.
- 1440px에서 챕터/판례 각 531px 동등 2열, 삭제 대상 패널 0개. 편집기 시작 위치는 변경 전보다 약 476px 올라왔다. 기존 본문 textarea 규칙이 머리글에 적용되던 240px 높이는 최종 64px로 보정했다.
- 390px에서는 두 영역이 세로 배치되고 가로 넘침이 없다. 머리글 끄기→자동 저장→재진입, 켜기→문구 편집→STEP4 동기화, Markdown fallback의 본문·표·이미지 보존을 실제 DOM에서 확인했다.
- 명함 삭제 취소(요청 없음), 503 실패(카드 유지·재시도 가능), 재시도 성공(목록 제외), DB관리 보관→복원, 직원 계정 삭제/복원 버튼 미노출을 합성 화면에서 확인했다.
