# CF97 — 상단 편집 도구, 양면 보기, 다중 빈 줄, F4

## 변경 범위

- 제안서·보고서 공통 편집기에 표/이미지/AI 버튼을 모았다. AI 요청란은 버튼으로 펼치며, 기존 원문 비교·승인·업로드 경로는 유지한다.
- 도구 아래 동일한 폭의 편집/출력 두 면을 배치한다. 최초 배율은 나란히 맞춤이며 75%/100% 선택 가능하다. 650px 이하 작업 영역은 세로로 배치한다.
- 표시 배율은 native CSS zoom이며 문서 치수·저장 JSON·출력 renderer는 바꾸지 않는다. 보고서 옆 미리보기는 본문부터 보여 주고 최종 출력의 갑지는 유지한다.
- Ctrl/Meta+빈 줄 클릭은 선택을 추가/해제한다. 선택 위치는 ProseMirror 플러그인에서 mapping하며 문서에 저장하지 않는다. 숫자 입력을 위해 포커스를 옮겨도 선택을 유지한다. 일괄 적용/삭제는 한 transaction이다.
- F4는 마지막 성공한 편집의 의미와 값을 현재 선택에 재적용한다. 글꼴/크기/색상/굵게·기울임·밑줄/문단 정렬/빈 줄/표 삽입·행열 편집/표·이미지 서식/열행 치수를 지원한다. 굵게는 토글 결과를 반복한다.
- undo/redo는 별개다. AI 호출, 업로드, 저장은 반복하지 않는다. 입력폼, 읽기전용, 다른 문서에서는 이전 행동을 실행하지 않는다.

## 검증

- `/qa/document-review.html`: 업무 데이터 없는 실제 공통 편집기. `왕복 검증 실행`은 기존 10개 왕복 계약과 실제 ProseMirror 상태를 사용하는 7개 편집 계약을 실행한다.
- 다중 선택/토글, 선택 앞 삽입 후 위치 매핑, 일괄 간격/삭제, 한 번 undo, 새 대상 서식 반복, 굵게 재반복, 표 행열 반복, readOnly 방어 포함.
- 실제 Chrome에서 별도로 키보드 F4, 숫자 입력, Ctrl 클릭, 표 경계 드래그, 배율과 반응형 레이아웃을 검사한다.
- CSS zoom에서 기존 라이브러리가 화면 px와 원본 px를 혼용하므로 public resize hook에서 보정한다. 75%에서 36px 이동하면 원본 치수는48px 변한다. 무이동 클릭은 치수를 바꾸지 않는다.
- F4 키는 현재 키보드 선택 갱신 다음 프레임에서 실행하며, 표 대화상자 완료 직후에도 편집기로 포커스를 복원한다. 버튼 경로와 같은 액션 함수를 사용한다.
- CF60/91/95/96의 정적 검사는 동일 기능이 새 공통 컴포넌트/액션 모듈로 이동한 경로로 갱신한다. 기존 출력/자동저장 회귀도 함께 실행한다.

### 확인 결과

- 관련 회귀 36/36, 브라우저 왕복·편집 계약 17/17, 타입 검사 및 프로덕션 빌드 통과.
- 실제 F4 키로 새 선택의 굵게·글꼴, 빈 줄 삽입·간격, 대화상자에서 지정한 3행×2열 표 반복을 확인했다. 입력폼에서는 반복하지 않는다.
- Ctrl로 빈 줄 3개 선택 → 48px 일괄 적용 → 한 번 취소 → 다시 실행, 전체 선택 해제 후 새 빈 줄만 선택하는 경로를 확인했다.
- 1440px 맞춤에서 양쪽 용지는 655.99px, 시작 Y는 352.76px로 같았다. 1280/800px 및 보고서도 동일 폭·시작 위치이며, 좁은 모바일 영역은 세로 배치한다.
- 출력 옆 미리보기와 독립 4단계 렌더의 페이지 치수·여백·페이지 수가 같고, 75% 배율에서 표·이미지 드래그의 실제 저장 치수를 확인했다. 이미지 축소 시 최소 높이와 비율도 유지한다.
- 보고서는 업무 데이터 없는 공통 편집기에서 확인했으며, 기존 업무 문서를 수정하거나 새 HWP/PDF 산출물을 생성한 검수는 아니다.

## 보호 범위

API, DB, migration, 환경변수, 실제 업무 문서는 변경하지 않는다. 실제 사용 중인 미저장 브라우저 탭은 새로고침하지 않는다. 보고서 출력의 페이지 분할 알고리즘과 HWP/PDF 엔진은 이번 변경 대상이 아니다.
