# CF96 — 동시 편집·출력 미리보기와 명시적 빈 줄 간격

## 범위

- 제안서 3단계: 왼쪽 목차/공통 모듈, 가운데 편집, 오른쪽 동일 출력 렌더러. 갑지·목차도 오른쪽 표시.
- 테스트 서버 보고서 3·4단계: 단일 편집기와 기존 최종 출력 렌더러를 좌우로 배치. 승인본 다운로드 ref와 분리하여 페이지 중복 수집 방지.
- 읽기 전용 결과만 화면에 맞춰 축소. 편집 DOM에 transform을 적용하지 않아 표 경계 드래그 좌표를 보존.
- 빈 줄은 1~240px의 명시적 documentSpacer. 클릭 후 높이 변경·삭제, undo/redo 지원. 이웃 문단 여백 중복은 동일 CSS로 제거.
- 빈 문단 개수를 쪽 나누기로 추측하지 않음. 기존 명시적 documentPageBreak는 보존하며 선택 후 간격 적용으로 사용자가 빈 줄로 바꿀 수 있음.
- JSON과 Markdown 양쪽에 간격/쪽 나누기를 보존. Turndown의 blank rule이 사용자 rule보다 먼저 실행되는 경로와 hardBreak 문단도 처리.
- 보고서 저장 중 JSON만 바뀐 경우 최신 ref와 요청 snapshot을 비교하여 미저장 상태 유지.
- 여러 셀 선택 상태에서 간격 삽입 비활성화. 표 셀/인용문 안 이미지 뒤 삽입 위치 보정.

## 검증

- 담당 세 에이전트: 브라우저·코드 경로·회귀 독립 읽기 전용 감사. 코드 수정/통합은 총괄만 수행.
- CF07/60/66/67/68/69/91/93/94/95/96: 36/36.
- 전체 workspace typecheck 및 build 통과. 기존 대형 번들 경고는 남음.
- 로컬 실제 브라우저 fixture `/qa/document-review.html`: 10/10 계약 검사.
- 24→48px 적용: 노드 중복 없음, undo24/redo48, Markdown 재열기 후48px. 제안서/보고서 출력 원본 높이도48px.
- 별도 PM runtime 감사: 빈 문단/hardBreak/간격/쪽나누기/이미지 JSON→HTML→Markdown→HTML→JSON 5회 보존. 표 셀/blockquote 이미지 삽입 및 다중 셀 안전성 확인.
- CF67의 두 기대값은 기준 HEAD부터 실패한 오래된 문자열 검사: searchable 속성 및 workspaceDirty 보호를 수용하도록 테스트만 갱신. 앱 기능을 되돌리지 않음.

## 범위 밖·주의

- 보고서는 기존 가로 용지와 최종 출력 동작을 유지. 이번 UI 변경이 보고서의 canvas 기반 긴 본문 절단을 의미 기반 페이지 나눔으로 교체한 것은 아님.
- 보고서 실제 계정에는 연결 가능한 프로젝트가 없어 라이브 저장/승인 전체 경로는 검증하지 못함. 동일 컴포넌트 로컬 검증과 기존 D1 저장 회귀를 사용.
- 별도 서버 finalDocument API가 JSON 없이 content로 출력하는 기존 경로는 이번 수정에 포함하지 않음.
- 기존 문서의 쪽 나누기는 수동/과거 자동 변환을 구분할 수 없으므로 일괄 삭제하지 않음.
- 새 DB migration/환경변수/비밀값 변경 없음. 이전 구현 기준은 `7a48d35`이며 롤백 시 서버 DB를 교체하지 않음.
- `apps/web/qa`는 로컬 Vite 검증 전용으로 production index와 라우터에 연결하지 않음.
