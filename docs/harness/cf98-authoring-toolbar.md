# CF98 — 직접작성과 편집 도구 가독성

## 범위와 원인

- 2단계 textarea가 저장용 HTML 표와 글꼴 span을 문자 그대로 보여 주고, 수정 시 editorJson을 폐기했다. 기존 StructuredDocumentEditor로 표시·편집하며 body와 JSON을 함께 저장한다.
- 기존 1~3장 기본 초안 또는 사용자가 수정한 내용을 그대로 표시한다. 원본 HWP의 완성 예문을 새로 추출하는 변경이 아니며 템플릿 재주입은 하지 않는다.
- 글꼴·크기 라벨을 숨기던 테마 규칙을 제거하고 글자 서식 행을 구분한다. 표/이미지/AI 버튼은 색상뿐 아니라 텍스트 이름으로 구별한다.
- 편집/출력 제목만 13px에서 19.5px로 키우고 각각의 흰 상자에 중앙 정렬한다. 용지 크기·배율·본문 글자·출력 계산은 그대로다.
- 선택 메뉴는 축소·스크롤 용지 밖 body에 fixed로 표시하고 실제 편집 패널 스크롤을 감시한다. 복사·서식·AI 동작은 기존 경로를 사용한다.
- 브라우저가 색상을 `rgb(...)`로 직렬화한 경우도 공통 색상 정규화에서 HEX로 보존한다. 가져온 13px 등 유효한 크기도 메뉴에서 실제 숫자를 표시한다.

## 보존 경계

API, DB, 환경변수, 배포 설정, PDF/HWP 엔진은 변경하지 않는다. MANUAL 저장은 기존 chapters를 사용하며 AI용 입력 재생성 경로를 사용하지 않는다. 구조화 JSON을 레거시 중복본문 복구로 덮어쓰지 않는다.

2단계에서만 plain-text Markdown/HTML 붙여넣기를 기존 sanitizer와 ProseMirror parser로 해석한다. 리치 HTML 붙여넣기는 기존 편집기 동작을 유지한다. 빈 문단·빈 표·간격 마커만 있는 초안을 완료 처리하지 않되, HWP 페이지 이미지 등 정상 콘텐츠는 유지한다.

## 검수 경로

- 기존 회귀 36개 + `scripts/cf98-authoring-toolbar-test.ts` 3개.
- `/qa/document-review.html`의 기존 편집 계약, 직접작성 내용 판정, Markdown 예시 복사→붙여넣기→검수 전환.
- 실제 선택 메뉴의 75%/맞춤/전체화면/내부 스크롤, 선택 대상에만 글꼴·크기 적용.
- 1440/1280/390px 컨테이너 폭, 라벨·숫자 단위 표시, 좌우 용지 폭·시작 위치 유지. 390px는 실제 모바일 기기 검사가 아니다.
- CF97 F4 키, Ctrl+빈줄 다중선택, 표·이미지 배율 보정의 회귀 보존.
- 실제 업무 문서는 변경하지 않고 로컬 검수용 문서에서 편집한다. 배포 확인도 별도 탭에서 읽기 전용으로 수행한다.

- 자동 회귀 39/39, 브라우저 계약 19/19 통과. 타입 검사·프로덕션 빌드 통과(기존 큰 번들 경고 유지), 레이아웃 기계 검사 0건.

- 내부 패널 가로 스크롤 96px 이동 시 선택 범위와 메뉴가 함께 96px 이동하며 약 8px 간격을 유지했다.
